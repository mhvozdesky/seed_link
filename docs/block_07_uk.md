# Block 07 — Автономний HTML

## Реалізований контракт

- `write_html_report(result, path, exported_at=...)` приймає повний незмінний
  `ReportResult` і створює один `.html`/`.htm`, який не потребує сервера, CDN,
  мережі або встановлених користувацьких бібліотек.
- `build_html_projection(...)` формує окрему whitelist-проєкцію. Вона не
  серіалізує телефони й пошту лідів, пошту учасників, сирі відповіді R1,
  результати/нотатки R4, значення джерельних клітинок або `Issue.details`.
- Проблеми містять лише код, рівень, структуроване повідомлення, вплив, стан і
  координати `роль / аркуш / рядок / поле`. Повна відповідність людей лишається
  у desktop та Excel.
- Шаблон Jinja2 використовує escaping і `StrictUndefined`. JSON усередині
  `<script type="application/json">` додатково екранує `<`, `>`, `&` та Unicode
  line separators, тому джерельний текст не може завершити script.
- Усі значення з payload додаються в DOM лише через `textContent`; `innerHTML`
  не використовується. CSP забороняє мережеві з’єднання, зовнішні ресурси,
  об’єкти, форми та base URL.
- Вбудовані CSS і JavaScript реалізують огляд, чотири Canvas-графіки, пошук,
  сортування, таблицю ваучерів, учасників, товарних рядків, інших ваучерів,
  проблем і метаданих.
- Фільтри учасників, основних ваучерів, товарних рядків, інших ваучерів і
  проблем незалежні. Скидання одного набору не змінює інші.
- Кількості передаються десятковими рядками. Суми й порівняння в JavaScript
  виконуються через масштабовані `BigInt`; `Number` використовується лише для
  довжини стовпчиків Canvas, а не для показаного бізнесового підсумку.
- Процентні картки зберігають точний Decimal у payload, але для читабельності
  показують значення, точно округлене через `BigInt` до одного знака після коми.
- Сортування таблиць використовує accessor із визначення колонки; складені
  значення на кшталт культур і координат джерел сортуються за тим самим текстом,
  який бачить користувач.
- Payload містить контрольні підсумки Python. Після відкриття JavaScript
  повторно агрегує вихідні HTML-факти й показує стан збігу на огляді.
- Ознака проблеми пари лід–ваучер використовує спільний domain helper
  `link_related_keys`; query, Excel і HTML однаково враховують link, LeadRef,
  voucher, Survey, mention та ProductLine ключі.
- Пошук у товарних рядках не відкидає нематеріалізовані невідомі внески:
  для конфліктного Product ID немає дозволеного текстового рядка, за яким можна
  було б довести його невідповідність пошуку. Структурні фільтри й надалі
  застосовують правила `query_product_lines`.
- Помилка структури payload або виконання JavaScript перехоплюється на верхньому
  рівні й показує зрозуміле повідомлення замість порожньої сторінки.
- Метадані містять calculation/snapshot ID, ревізію, час, версію програми,
  повноту комплекту, ролі, файли, схеми, кількість рядків і SHA-256.

Атомарна публікація пари Excel+HTML не входить у цей блок: її координуватиме
`ExportService` у Block 09.

## Автоматичні перевірки

Тести перевіряють:

- whitelist payload і відсутність конкретних значень телефону, пошти, сирої
  відповіді та нотатки як у JSON, так і в готовому файлі;
- відсутність небезпечних ключів і сирих `Issue.details`;
- escaping `</script>` та HTML-подібного клієнтського тексту;
- відсутність зовнішніх `src`/`href`, URL і `innerHTML`, наявність CSP;
- точні рядки `0.1 + 0.2 = 0.3`, невідомі внески та Python control totals;
- `VOUCHER_NOT_FOUND` на Survey/mention ключах однаково впливає на
  `query_lead_vouchers`, Excel і HTML-ознаку `hasIssues`;
- Node DOM-harness реально виконує готовий `report.js`, перевіряє початковий
  self-check, незалежність фільтрів і порівнює фільтровані результати з
  `query_product_lines` та `query_lead_vouchers`;
- пошук за ваучером не губить нематеріалізований внесок конфліктного Product ID;
- частка `2 / 3` лишається точною в payload і показується як `66,7 %`;
- колонка «Культури» сортує два ваучери за видимим текстом у двох напрямках;
- усі чотири графіки мають одиниці в підписах;
- коректний порожній звіт і валідацію суфікса/часового поясу;
- синтаксис вбудованого JavaScript і тестового Node-harness.

## Приймальний бар’єр

Автоматичні Python-перевірки та виконання готового JavaScript у Node DOM-harness
пройдено. Запуск через browser automation у `file://` був заблокований
політикою самого контролера браузера, а не кодом звіту. Тому остаточну ручну
візуальну перевірку сценарію H01 на Windows із вимкненою мережею потрібно
виконати у Block 10: відкрити файл подвійним кліком, перевірити чотири графіки,
усі фільтри/сортування, порожні вибірки та зелений індикатор збігу контрольних
підсумків.
