# Block 02 — результат реалізації

## Поведінка

- `read_workbook()` перевіряє конкретний слот R1–R4, а
  `import_workbooks()` завжди перевіряє всі чотири слоти й створює
  `InputSnapshot` лише без блокувальних проблем.
  `INTERNAL_ERROR` також є фатальним і не дозволяє створити snapshot, але не
  видається за пошкоджений файл користувача.
- Розширення `.xlsx` є обов'язковим. Додатково перевіряються частини й тип
  OOXML-пакета; CSV/HTML/XLS, довільний ZIP, зашифрований файл і книга з
  макросами не приймаються.
- Підтримується рівно один аркуш, заголовки у першому рядку та точний набір
  колонок версії 1. Порядок колонок і назви файла/аркуша довільні. Для зміни
  схеми повертаються окремі списки відсутніх, доданих, дубльованих і порожніх
  заголовків; точна схема іншої ролі дає `ROLE_MISMATCH`.
- Правильна шапка без даних допустима. Повністю порожні фізичні рядки не
  створюють записи; приховані та відфільтровані рядки читаються.
- Один і той самий масив байтів використовується для SHA-256 і читання, тому
  метадані відповідають фактично завантаженому знімку. Імпорт не записує у
  джерельні книги. Шлях до файла залишається лише в оперативному результаті
  читання; `InputSource` у snapshot містить тільки назву файла й не може
  випадково передати абсолютний шлях до звіту.
- Кожна клітинка запису зберігає роль, файл, SHA-256, аркуш, Excel-рядок,
  поле, оригінальне значення, тип значення і ціль нативного hyperlink. Формули
  читаються як формули з `data_only=False`, не обчислюються і стають
  `UNSUPPORTED_CELL_VALUE`.
- Рольові `R1Record`–`R4Record` містять потрібні нормалізовані ID, дати,
  кількість і текстові атрибути, не змінюючи сирі значення. Цілий числовий ID
  лишається доступним для часткового результату, але завжди створює
  `NUMERIC_ID_RISK`: початкові нулі або точність могли бути втрачені ще в
  Excel. Дробовий чи інший непридатний тип ID не приймається.
- HTML у `Campaigm Member` не виконується: вузький `HTMLParser` лише збирає
  `href`. Campaign Member ID читається з інертного текстового фрагмента або
  нативного hyperlink без припущення про префікс `00v`. Підтримуються 15 і 18
  символів: 15-символьний ID приводиться до 18-символьного, а спільний
  `salesforce_id_key()` готує їх до точного порівняння у Block 03. Непорожнє
  посилання без ID створює `CAMPAIGN_MEMBER_ID_INVALID`, а не зникає мовчки.
- Ідентичні рядки з однаковим стабільним ID мають один representative record і
  всі джерельні посилання. `record_accounting` завжди повертає пару:
  `countable_records` та `uncertain_groups`; `is_complete=False` не дозволяє
  трактувати конфліктну групу як нуль. Суперечливий ID не отримує довільного
  переможця. Повністю однакові рядки без ID утворюють
  `DUPLICATE_UNCERTAIN`; різні рядки без ID залишаються окремими внутрішніми
  записами.
- Винятки на межі відкриття або лінивого читання openpyxl класифікуються як
  пошкоджений XLSX. Винятки власного рольового парсингу чи групування дають
  `INTERNAL_ERROR`, діагностичний код і стек без значень джерельних клітинок.

## Перевірки

`.venv/bin/python -m pytest` покриває порожні книги, довільний порядок колонок,
неправильний слот, усі види різниці схеми, не-XLSX, кілька аркушів, приховані
рядки, формули, текстові/нативні посилання, 15↔18 Salesforce ID, посилання без
ID, порожні R3 ID, початкові нулі, числові ID, дублі, конфлікти та ін'єкцію
внутрішнього `KeyError`. Локальний integration test звіряє справжні книги з
незалежним маніфестом: 3/117/9/3 записи та зафіксовані SHA-256, а також повторно
рахує SHA-256 після імпорту. Якщо приватних книг немає, цей тест пропускається.

Додатково виконуються `compileall`, `pip check`, `git diff --check` і
smoke-імпорт реального комплекту без зміни його файлів.

## Відомі межі

Block 02 не групує Survey у бізнесові сутності, не зіставляє людей або
ваучери та не обчислює показники. Block 03 має споживати весь
`record_accounting`, а не лише `countable_records`, щоб передати неповноту до
воронки. Побудова `Survey`, `Participant`, `Voucher`, `ProductLine` та зв'язків
належить Blocks 03–04.

R1 навмисно читається без `read_only`, бо тільки звичайні `Cell` зберігають
потрібні native hyperlinks. Якщо R1 суттєво виросте, його пам'ять і час треба
окремо виміряти у сценарії W04; R2–R4 вже читаються у `read_only`.
